# 2026-09-21 · my-baby-moments 从零搭建

需求：两个宝宝（3 岁 / 9 个月）的成长展示页，形态像微信朋友圈，媒体按 `yyyy-MM-dd` 目录组织、一天可多条、自动整理并展示。走 taste-skill（design-taste-frontend）做非模板化设计。

## 最终架构

零构建前端（裸 DOM + `<svg><use>` 内联图标雪碧图）+ Node 服务端（`sharp` + `heic-convert` 两个依赖）。
唯一需要用户编辑的文件是 `moments.config.mjs`。

```
moments.config.mjs   site / paths.mediaRoot / kids / feed / media / thumbs / server
src/util.mjs         自然排序、路径编解码、ageAt、限流器、DATE_DIR_RE
src/scan.mjs         目录 → manifest，增量缓存 .cache/filemeta.json（mtimeMs+size）
src/thumbs.mjs       多级解码链 + 磁盘缓存
src/manifest.mjs     URL 装饰层（serve / build 共用）
src/server.mjs       feed / SSE / 缩略图 / Range 媒体流
src/cli.mjs          serve | scan | build | clean
public/index.html    骨架 + 图标雪碧图 + <!--SITE_CONFIG--> 注入点
public/assets/{style.css,app.js}
scripts/fetch-icons.mjs   幂等拉 22 个 Phosphor 图标内联
scripts/seed-demo.mjs     生成示例照片库
```

## 目录约定（核心）

`photos/yyyy-MM-dd/[001-条目名/]`；日期目录下子文件夹 = 一条动态，散落文件每文件一条。
`caption.md` / 同名 `.md` 提供文案，`meta.json` 提供 kid/title/location/time/notes/media。
`001-` 前缀控顺序；`meta.time` 优先。与视频同名的图片自动当封面（`role: 'poster'`，不进九宫格）。

## 踩过并修掉的坑（都值得记住）

1. 🔴 **HEIC/HEVC 解码**：`sharp` 预编译包只认得 HEIC 容器头、解不了 HEVC 像素（`bad seek to N`，5 种写法全败）。
   改用 `heic-convert`（libheif WASM）作为 HEIF 首选路径 → `sharp` → macOS `sips` 兜底。实测 ~292ms/张。
2. 🔴 **Phosphor 图标没有 `fill` 属性**：雪碧图里的 `<path>` 不带 `fill`，CSS 又没设，
   ⇒ 所有图标被解析成 **纯黑**。浅色顶栏看不出问题，但灯箱、封面遮罩、视频播放按钮上图标**直接消失**。
   修法：`svg { fill: currentColor }` + `fetch-icons.mjs` 写出的 `<symbol>` 自带 `fill="currentColor"`。
   验证手段：CDP 探针读 `getComputedStyle(svg).fill`（黑→白才是真的修好了）。
3. 🔴 **`fetch-icons.mjs` 原本不幂等**：替换串里把 `MARK_START` 剥掉了，标记被自己的输出吃掉，
   第一次跑成功、第二次报「找不到占位标记」。改成两个标记都写回，连跑 3 次 md5 一致。
4. 🔴 **视频 poster 的 key/rev 取错了对象**：`thumbUrl(m, 'view')` 里的 `m` 是视频，而视频只生成 `grid` 一个变体
   ⇒ 拼出一个永不存在的地址、静默 404。必须用**封面图**对象的 key/rev。症状是视频封面黑掉但控制台无报错。
5. 🔴 **静态导出 → `/media/*` 不存在**：`build` 默认不复制原图，但 URL 仍指向 `/media/*`。
   加 `mediaAvailable` 开关：false 时视频 `src=null` + `playable=false`、poster 退到封面图的 view 缩略图、动图 `view` 退到缩略图。
   前端据此不播视频、只显示封面 + 播放按钮，灯箱弹「这一版静态导出没有带上原视频」而不是黑屏。
6. 🟡 **`seed-demo.mjs --force` 原本 `rm -rf photos/`**：对已经放了真实照片的目录是危险设计。
   改成只清理脚本自己生成的那些条目（`demoPaths()` 返回 entries + dirs，删空目录用非递归 `rmdir`）。
   已实测：放入 `004-用户自己的照片.jpg` 后跑 `--force`，示例条目完整重建、用户文件幸存。
7. 🟡 **`zsh` 不做变量分词**：`for args in "--themes light --shots viewport"; ... $args` 整串被当成一个参数
   （`--themes` 的值变成 `light --shots viewport`），脚本静默按默认跑。要么显式写全，要么用数组。
8. 🟡 **`grep "A\|B"` 在 BSD grep 下静默返回空**（本轮又踩两次）——核验自己刚改的文件时也会踩。
   一律用 Grep 工具或 `grep -E "A|B"`。
9. 🟡 探针自身会骗人：第一次查视频时只数了 `.moment__play`，漏了 `<video>`，
   差点得出「视频渲染成普通单图」的错误结论。**探针要覆盖所有可能的渲染分支再下结论。**
10. macOS 沙箱内 `qlmanage` 起不来（`sandbox initialization failed`，`dangerouslyDisableSandbox` 也不行），
    `ffmpeg` 本机没装 ⇒ 视频抽帧失败。因为示例库给视频配了同名封面图，UI 走 poster 分支，不受影响。

# 追加 · 页面直接发布（`POST /api/upload`）

需求：为了能自动分组，加一个「类似发朋友圈」的上传入口 —— 用户不想自己去建 `yyyy-MM-dd` 文件夹和编号目录。

## 落盘链路（`src/upload.mjs`，529 行）

`POST /api/upload` 是全项目唯一的**写路径**，直接改动照片库，所以走两段式：

1. **手写流式 multipart 解析器**（不引 busboy/formidable）。`push(chunk)` 返回 Promise，
   调用方 `for await (const c of req) await parser.push(c)` ⇒ 背压天然成立。
2. **先写 `<cacheDir>/uploads/<token>/`**（照片库之外）⇒ 扫描器看不到半成品目录。
3. **校验通过后才进临界区**分配序号 + 建目录。`chain = chain.then(fn, fn)` 串行化，并发不撞号。
4. **`rename` 搬进 `photos/<日期>/<序号>-<标题>/`**；照片库在移动盘上会 `EXDEV`，退化成 `copyFile` + `unlink`。

目录名：`title ? \`${pad(seq,3)}-${title}\` : pad(seq,3)`，撞名则 `seq += 1` 重试（上限 200）。

## 与本项目既有约定的咬合点（关键，改的时候别破坏）

- **同名文件共用序号**：`IMG_1234.jpg` + `IMG_1234.mov` → `001.jpg` + `001.mov`，
  正好命中扫描器「与视频同名的图片当封面」规则 —— iPhone 实况照片天然就是这个形状。
- **纯序号目录视为无标题**：`scan.mjs` 加 `ORDER_ONLY_RE`，否则上传产生的 `003` 会被显示成标题 "003"。
- **`scan.mjs` 新增 `dir` 字段**（`singleFile ? slice(0,slash) : entryKey`）。
  顺手修掉老 bug：前端 `buildMenu` 读的是不存在的 `entry.path`，一直拼出 `photos/undefined`。
- **`siteConfig()` / `toScriptJson()` 提到 `manifest.mjs`**，serve 与 build 共用，避免两边结构跑偏；
  build 注入 `uploadEnabled: false`。
- **`cmdClean` 顺手清 `.cache/uploads`**（上传中断会留半截临时文件），不带 `--all` 也清。

## 前端发布面板（`public/index.html` + `app.js` + `style.css`）

贴底/居中浮层：拖拽（拖到浮层任意位置都算，`dragleave` 靠 `relatedTarget` 排除内部元素）、
点选、`⌘V` 粘贴、缩略图预览、文案自增高、日期/时间/宝宝 chip、`<details>` 收标题与地点、进度条。
**用 XHR 不用 fetch**（fetch 拿不到上传进度，`xhr.upload.onprogress` 才有）。

- **`initPublish` 里 `if (!cfg?.enabled) { btn.hidden = true; return; }`** —— 提前 return 意味着
  一个监听都不挂，所以即便有人手动摘掉 `hidden` 也点不开面板。这是第二道防线。
- **SSE 静音窗口**：上传接口自己广播一次，`fs.watch` 的 debounce 还会再来一次 ⇒
  `state.muteLiveUntil = Date.now() + 2000` 挡住第二次刷新。
- **`toast()` 必须提在 `await fetchFeed(true)` 之前**：重扫大照片库要时间，否则面板关掉后页面毫无动静。

## 本轮修掉的坑

1. 🔴 **`Date` 会静默修正非法日期**：`parseDateOnly` 内部走 `new Date(y, m-1, d)`，
   `2026-13-45` 被**进位**成 `2027-02-14` ⇒ 上传成功且建出一个奇怪的日期目录。
   必须回读 `getFullYear/getMonth/getDate` 与原始三段逐一比对。
2. 🔴 **multipart 分隔符要多看 2 字节**：数据里也可能出现 `\r\n--boundary`，
   只有后跟 `\r\n` 或 `--` 才是真分隔符 ⇒ `KEEP = SEP.length + 2`。
3. 🔴 **浏览器把换行统一成 CRLF**：落盘前 `.replace(/\r\n?/g, '\n')` 归一，否则 `caption.md` 风格与手工文件不一致。
4. 🔴 **`OPTIONS` 预检原本回 `Allow-Origin: *`** —— 等于给任意网站开了写接口的门。改成只回显同源 Origin。
5. 🔴 **CDP `Page.captureScreenshot` 的 `clip` 恒为文档坐标**，与 `captureBeyondViewport` 无关。
   `captureBeyondViewport: false` 并不是「clip 变成视口坐标」，而是「不渲染视口外内容」⇒
   裁到当前滚动位置之上会返回**纯色空图**，而文件照样写出、退出码照样 0。
   更麻烦的是 sticky 元素（顶栏）：整页渲染里它的位置与 `getBoundingClientRect` 读数**不一致**，
   实测小屏会裁到 `.meta-line`。✅ 最终做法：**整视口原样截屏 + 用 sharp 按视口坐标裁**，只有一套口径。
   并且**给截图加像素断言**（统计主色像素命中数 / 色相桶数），否则空图也能静默通过。
6. 🟡 **断言不要硬编码主题色**：暗色的 `--accent` 与亮色不同（`rgb(113,193,168)` vs `rgb(31,111,92)`），
   主色断言必须从 DOM 读 `getComputedStyle` 回来。
7. 🟡 **`.iconbtn__label` 必须钉死 `line-height: 1`**：默认继承 body 的 1.6 ⇒ 13×1.6=20.8px，
   把带文字按钮撑到 **34.8px**，比只有图标的 `--iconbtn--solo`（34px）高 0.8px。
   改完三个按钮严格 34px、等距 6px。
8. 🟡 **安全闸门不能写成恒真条件**：`TMP_MEDIA` 是从 `WORK` 派生的（`WORK/photos`），
   写「TMP_MEDIA 是否包含于 WORK」**结构上永远为真** —— 是死代码，只给虚假安全感。
   真正要守的是：① `WORK` 落在 `<root>/.cache/` 内；② `WORK` 与真实 `mediaRoot` 互不包含。
   已用「把 WORK 指向 `photos/`」实测过闸门会 exit 2 且照片库完好。

# 第二轮：上传账号认证 + 多人并发不串组 + 时间可排序前缀

需求原话：①「上传操作需要账号认证，并且需要兼容多人同时上传的时候分组不能乱的问题」；
②「可以考虑分组用 nanoid，不一定非得使用数字。只要按照时间能排好序就行」。

## 对需求②的技术纠正（重要）

**nanoid 是纯随机字节打散，字典序与时间无关**，恰好不满足"按时间排序"。
要实现必须用**带时间前缀的变体**（ULID / KSSortableID 那一类）。
因此按真实约束设计，而不是照抄库名：`HHmmss`（定长 6 位）+ `-` + 4 位随机。
定长数字串的字典序**恰好等于时间序**，扫描器不需要额外解析。
随机字母表去掉易混字母：`0123456789abcdefghjkmnpqrstvwxyz`（去 i/l/o/u），
且 `256 % 32 === 0` ⇒ 取模无偏斜。

## 需求①的两个真实缺陷（探针实测，非猜测）

| 探针 | 修复前 | 修复后 |
| --- | --- | --- |
| 分组原子性（`setImmediate` 轮询日期目录） | 1654 轮询 / **503 次半成品**（最差「目录已建、0 个文件」） | 3038 轮询 / **0 次** |
| 跨进程序号（3 进程 × 3 条） | `1,2,2,3,3,4,5,5,6`（重复占号） | `1..9` 连续唯一 |

- **原子性**：整条动态先在 `<cacheDir>/uploads/<token>/entry/` **组装成完整目录**
  （媒体改名、`caption.md`、`meta.json` 全在库里落定），再用**一次 `rename`** 入库。
  临界区只有一次 rename，大文件搬运（可能几百 MB）发生在锁外。
- **跨进程序号**：`mkdir` 的原子性做互斥（`<cacheDir>/locks/date-<date>.lock`），
  进程内再叠一层按日期分桶的 Promise 链。

## 🔴 本机沙箱的两个"会静默改变结论"的坑

1. **`mkdir` 已存在的 `code` 被改写成 `CODEBUDDY_BROKER_DENY`**，只在 `message` 里留
   `EEXIST:` 前缀。只看 `code` ⇒ 判定成"锁不可用" ⇒ 把跨进程锁**静默降级成进程内锁**
   ⇒ 正是"分组乱掉"的成因。⇒ `isExists` 同时看 `code` 与前缀；
   **判断不出来时直接回 503，绝不降级放行**。
2. 同处暴露的第二个缺陷：`lockRoot` 的 `mkdir` 用了 `.catch(() => {})`，
   且 `lockPath` 的 `mkdir` 带 `{ recursive: false }`。⇒ 改为无选项 `mkdir(lockPath)`
   + 锁根目录失败即抛。

## 鉴权设计要点

- 口令 `scrypt$1$N$r$p$salt$hash`（N=16384, r=8, p=1, keylen=32，
  `maxmem=64MB` 低于 Node 默认，不触发 `ERR_CRYPTO_INVALID_SCRYPT_PARAMS`）。
  **必须用异步 scrypt** —— 同步版阻塞事件循环，一波失败登录就能卡死服务。
- 比较用**定长比较**：先 sha256 对齐长度再 `timingSafeEqual`。
  直接比较在长度不同时会抛错，而"抛错"与"返回 false"耗时不同 ⇒ 泄漏"口令长度猜对了"。
- 账号不存在也跑一次假哈希（`dummyHash`），避免用响应时间枚举账号。
- 会话 = HMAC-SHA256 签名的 Cookie（`base64url(JSON).base64url(sig)`），服务端无状态。
  密钥落 `.cache/session.key`（0600），落盘失败退化成进程内临时密钥并警告。
- **Cookie 默认不带 `Secure`**：`http://127.0.0.1` 下带上则浏览器不保存，登录永远失败。
  走 https（或反代透传 `x-forwarded-proto: https`）时自动带上。
- 续期要在 `writeHead` **之前**下发新 Cookie（剩余不足一半有效期时）。
- 限流双维度：`ip:<IP>`（上限 `maxAttempts*3`）+ `id:<IP>|<账号>`（上限 `maxAttempts`），
  滑动窗口 + `429` + `Retry-After`，5000 条上限兜底清理。
- **`auth.enabled: true` 但 `users` 为空 ⇒ 上传回 503 `AUTH_NOT_CONFIGURED`，不静默放行**。

## 前端（`public/assets/app.js`）

- 顶栏「登录 / 发布」**互斥**（`renderAuthUI` 统一决定显隐），不会同时出现。
- 登录成功 → 关浮层 → **顺手打开发布面板**；发布面板底部常驻「以 X 的身份发布 · 退出」。
- **401 自动回登录且保留已选文件与已填内容**：`closePublish({ keepFiles: true })`
  跳过 `releasePreviews()`，`openPublish({ fresh: false })` 跳过字段重置，
  用 `pub.afterLogin` 记住"这次登录是为接着发"。
- 卡片底部署名：`⊙ 妈妈 13:35`，来自 `meta.json` 的 `author`（给人看）/ `authorId`（给程序用）。
- 新增图标：`sign-in` / `sign-out` / `user` / `user-circle` / `lock-simple` / `eye` / `eye-slash`。

## 🔴 前端新增元素时踩到的两个具体坑

1. **`[hidden]` 会被自己的 `display` 覆盖**：`.iconbtn { display: inline-flex }`
   比 UA 样式表的 `[hidden] { display: none }` 优先 ⇒ 每个用 `hidden` 控制显隐的
   按钮都要显式补 `[hidden] { display: none }`（`.iconbtn--pub[hidden]`、
   `.iconbtn--auth[hidden]`、`.sheet__who[hidden]`）。漏了按钮会一直显示，
   而且看起来"逻辑没问题"。
2. **页面里出现第二个 `.sheet` 后，`$('.sheet__scrim')` 就错了**：
   `querySelector` 永远只返回文档里第一个。已改为 `$('#publish .sheet__scrim')`。
   ⇒ 新增同类组件时，凡 `$('.class')` 形式的全局选择器都要过一遍。

## 🔴 无头 Chrome 在本机的可用参数（来自 headless-visual-audit skill，实测复现）

CDP 在**沙箱内不通**：WS 握手能成功，但第一句 `Page.enable` 永久静默超时。
根因不是"Node 被沙箱限制"，而是 **Chrome 自身的 sandbox 初始化失败**
（`sandbox initialization failed: Operation not permitted`），连带 GPU 进程
`exit_code=6`、整个浏览器退出 ⇒ WS 被关闭。必须同时：
- `--no-sandbox`（关掉 Chrome 自带沙箱）
- `--no-proxy-server`（环境里有 `HTTP_PROXY` 时，Chrome 会把 `127.0.0.1` 也走代理，
  导航落到 `chrome-error://chromewebdata/`，所有探针读到 `null`）
- `--disable-gpu`、`--disable-dev-shm-usage`
- `--remote-debugging-port=0` + 从 `<udd>/DevToolsActivePort` 读回真实端口
- 外层执行环境也要**非沙箱**

排查手法：`chrome.on('exit')` + 抓 stderr 尾部，一眼就能看到 `Goodbye.`。
另外同一实例上探针失败后重试必然连带失败 ⇒ 每次尝试起**全新** Chrome（新 `user-data-dir`）。

## 截图取数的两个坑（本轮再次踩到）

1. **`Page.captureScreenshot` 的 `clip` 恒为文档坐标**，而 `getBoundingClientRect()`
   是视口坐标 ⇒ 页面有滚动量时差一个 `scrollY`；元素在视口外时需
   `captureBeyondViewport: true`，否则只截到视口内的部分（表现为大片空白）。
2. **不要用肉眼判断缩略图里的配色**。本轮暗色登录面板在缩略图里看着"底色偏亮、
   与输入框不一致"，实测 `getComputedStyle` + **PNG 像素取样**后确认完全正确
   （暗色面板 `rgb(33,35,39)` = `--surface-2`、页脚 `rgb(29,31,34)` = `--surface`）。
   ⇒ 涉及配色的结论一律用实测值，观感只作参考。

## 顺带补上的仓库缺口

- **项目原本没有 `.gitignore`**：`node_modules/`、`dist/`、`.cache/`
  （含 `session.key` 签名密钥 + 缩略图 + 上传暂存）在 `git init` 时会被无差别纳入。
  已在 `.gitignore` 里注释说明为何整个 `.cache/` 都忽略，并注明 `photos/` 故意不忽略。
- `verify-upload.mjs` 的临时配置**必须显式 `auth: { ...base.auth, enabled: false }`**：
  它继承真实配置，若不关掉、而使用者恰好没配 `users`，服务会对上传回 503，
  于是这条用例测的就不再是"上传链路"而是"认证配置"了。这是完整验证链抓到的真实回归。
- `scripts/verify-ui.mjs` 的口令哈希**在运行时现生成**（`hashPassword`），
  不把哈希写死进仓库，换了 scrypt 参数也不会悄悄失效。

# 配色改版：改成微信朋友圈体系

用户要求「修改配色和微信朋友圈一致」。没有凭印象配色 —— 先查了 Tencent 官方
**WeUI 色彩 token**（微信小程序与微信本体同源），拿到权威色值后才发现真正的难点。

## 核心冲突：微信自己的配色大多不达标 WCAG AA

| 微信官方色 | 白底对比度 | 结论 |
| --- | --- | --- |
| `#07c160` 微信绿 | **2.38:1** | 只能做纯装饰 |
| `#10aeff` weui-BLUE | 2.46:1 | 不可用 |
| `rgba(0,0,0,.3)` FG-2 三级文字 | 2.10:1 | 不可用 |
| `#fa5151` weui-RED | 3.30:1 | 仅大字 |
| **`#576b95` 朋友圈昵称蓝** | **5.33:1** | ✅ **唯一天生达标的微信色** |
| 白字压 `#07c160` | 2.38:1 | 微信自己就这么用 |

又逐档压暗求解「同时满足①白字压其上 ②它当文字压白底 ③它当文字压灰底」的**最亮微信绿**：
k=64%（`#047c3d`）灰底 4.53:1 刚过线；k=66%（`#057f3f`）降回 4.36:1 不过。
⇒ 结论：`--accent`（装饰）与 `--accent-strong`（承载文字）**必须拆成两个 token**。

## 用户拍板

用 `AskUserQuestion` 收敛（技能明确要求；这里确实是 50/50 的可见分歧）：

- **主色取向：蓝绿分层** —— 可点文字/署名用朋友圈蓝 `#576b95`；按钮用微信绿实底 +
  深墨绿字；绿只做纯装饰。
- **底色结构：灰底 + 白卡**。

最关键的一个取舍：**绿按钮保住了原色，动的是字色**（白 → `#04240f` 深墨绿，6.96:1）。
微信用的是白字（2.38:1），达不到 AA。

## 取证时发现的事实与预期不符

**原来根本没有「每条动态一个白卡」**。`.moment` 是平铺的行（`padding: 16px 0 20px`，
无 `background`），白卡只用在浮层面板。底色一改灰、没有白卡会比原来的暖色底更闷
⇒ 补上白卡（**不加阴影**，灰底与白底本身已分得开），并补 `.moment + .moment` 间距与
`.day + .day` 段间距 —— 原先靠 `.moment` 的 padding 撑开，卡片化之后会塌。

## 静态验算抓到两处真实缺陷（CDP 审计看不到）

按**元素真实组合**算（不是抽象 token 对），首轮 46 通过 / 2 失败：

1. 🔴 **字母头像**：`#047c3d` 压在 `--canvas-2` 上只有 **4.14:1**
   （15px/600 不算大字，需 4.5）⇒ 底改成 `--accent-soft`（4.80:1）。
2. 🔴 **上传进度条**：`<div class="bar"><span class="bar__fill">` **没有任何数字标签**，
   填充长度是唯一信息载体 ⇒ 必须 ≥3:1，而 `#07c160` 压在轨道上只有 **1.86:1**
   ⇒ 改 `--accent-strong`（4.14:1）。

二轮 **50 通过 / 0 失败**。另有 2 项归入「已批准的取舍」：`--accent` 作大面积实底时
与页底只有 2.38:1（靠压在身上的 6.96:1 文字标签被识别；WCAG 1.4.11 约束的是
「识别控件**所必需**的视觉信息」）。

⚠️ 验算脚本**必须从真实 CSS 解析 token**，不能手抄色值 —— 手抄的话改了 CSS 却忘了改脚本，
验算会「通过」一个不存在的方案。

## 真实渲染审计（含强制补测盲区）

- 亮色 / 暗色 1280px：各 **101 个文本节点、各 1 项不达标**，且是同一个**既有假阳性**
  —— `.topbar__brand` 未吸顶时 `opacity: 0`，前景与背景都合成成 `--canvas`、比值恒为 1。
- **面板默认 `hidden`，属审计盲区**。用 `--css` 强制 `#publish` / `#login` 可见后补测：
  发布面板亮暗各 **21** 节点、登录面板各 **17** 节点，**四组全部 0 项不达标**。

## 顺手收口两处「不受控的 UA 默认色」

- **`placeholder`**：全站 5 个，此前**一条规则都没有** ⇒ 浏览器默认色
  （Chrome 还会跟着 `color-scheme` 在「半透明黑/白」之间切）。显式钉到 `--ink-3` +
  `opacity: 1`（后者给 Firefox —— 它默认还叠 .54 透明度）。
- **`::selection`**：默认系统蓝。先试半透明底 `color-mix(in srgb, var(--accent) 38%, transparent)`
  —— 文字对比度没问题（12.34:1），但**「选区 vs 页面底」浅色下只有 1.36:1**，
  绿本身太亮、叠在白底上压不出可辨识的色块 ⇒ 改成实色 `--accent` + `--accent-ink`
  （复用已验算的 6.96:1 / 7.22:1）。
- `<meta name="theme-color">` 同步为 `#ededed` / `#111111`（它不读 CSS 变量）。

## 顺带修掉的测试脆弱点（不是配色引起的）
